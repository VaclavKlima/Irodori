# Library browsing

Library is a persistent browsing workspace beside Editor. Its Images navigation icon identifies the full photo catalog; Editor uses the sliders icon and contains a compact Photos panel. Library presents every managed photo independently of stack expansion, using the same selection, actions, background task registry and deletion confirmation as Editor. Selecting in the browser changes selection and browser focus; opening a photo explicitly changes the editor's active photo. Browser ranges retain the accepted query and execute in arrival order with other selection gestures. Deletion awaits this queue before freezing its confirmation targets.

Actions and photo context menus follow the [menu design standard](menu-design.md). Library Actions uses browser focus after pending selection resolves. **Photo group** always means a persisted stack; date/month/year sections remain browser sections. Trash labels identify the focused photo, selection, or complete photo group, with equivalent targets deduplicated. Temporary task/lease blockers refresh while unrelated imports leave menus open. Confirmations say **Move photo to Trash?** or **Move N photos to Trash?** and initially focus Cancel.

Date, Month and Year headings can fold their thumbnail rows. Click a heading or focus its button and press Enter or Space. **Collapse all groups** reduces the current results to headings; **Expand all groups** reveals them again. Each grouping remembers its folds across completed workspace checkpoints, including across searches and visits to Editor. Group counts and selection checkboxes remain available when folded, and selecting a folded group still includes every matching photo. Folding never changes selection or range membership. Photo keyboard navigation skips folded groups, and folding the focused photo's group clears browser focus without changing the editor's active photo.

Fresh schema-17 catalogs create `photo_browse` and `browse_state` transactionally; current publication and metadata operations maintain them through the catalog writer. The index stores validated camera calendar date/time, searchable metadata, import timestamp, photo ID and date origin. Search splits whitespace into case-insensitive literal terms; every term must appear in one of the indexed fields. It has no query language. Ordering is camera calendar date/time descending, import timestamp descending, then photo ID descending. Dates are validated without converting timezone offsets into the computer's timezone. Missing or invalid dates are last.

Import and merge publication update the index in their catalog transactions. Metadata refresh updates stored processing metadata and the index together. Photo removal deletes its index entry through a catalog trigger; successful mutations increment the browse revision. Original and edit-history records retain their existing contracts.

Merge manifests freeze the configured reference's date in the result photo and processing metadata, with a `merge-reference` origin naming that source. Current publication writes the result's independent index row; its date remains available after the reference is deleted. Reopening preserves the stored index without a legacy migration or manifest rewrite. Older catalogs are unsupported and retain their original files.

The typed preload bridge exposes summaries, 60-photo chunks, photo locations, inclusive individual range references and complete section references. Summaries include matching and selected counts plus selections outside the query. Editing MCP exposes equivalent read operations without altering the existing flat-photo or stack-aware gallery APIs. Presentation reads can require a catalog revision; gesture reference reads retain their query and resolve against live managed records.

The [shared collection controller](scrolling-design.md) computes responsive columns, section headers, and fixed-height thumbnail rows. It renders the viewport plus two overscan rows and uses the main-owned conservative/standard/capable policy for bounded records, decoded thumbnail references, concurrency, and directional lookahead. Visible and keyboard-pinned items establish the cache minimum without enlarging cards. Folded groups retain headings and complete selection operations. Query and catalog generations reject stale chunks; ID/inset anchors restore after imports, deletion, grouping, and restart without overriding later scrolling. Catalog version 16 adds workspace checkpoints separately from photo history and browse revisions.

Verification targets are `all-photos-model` (Node), `all-photos` and `catalog-migration` (service), and `all-photos-ui` (Electron). Automated imports and deletion use isolated managed libraries and Trash adapters. Visual acceptance uses an isolated `dev:mcp` profile at 1100 × 700 with Console open; no performance benchmark or full checkpoint is implied by this feature.
