# Experimental Sony HDR merge and noise stacking

The Actions menu and photo context menu offer **Merge to HDR…** and **Stack for noise reduction…** for 2–32 selected photographs. Main validates every source: original Sony ZV-1/ZV-1A verified compressed RAW, matching camera, focal length, numeric shutter/ISO/aperture, and no known focus-distance changes. Aperture changes are permitted in HDR only when fresh managed-original capture facts prove one continuous BRK trigger, including a two-frame prefix. Other selections and noise mode retain the fixed-aperture and dimension restrictions. Group membership alone does not grant compatibility. Incompatible sources are rejected together; source edits are excluded.

The review uses reference selection, Auto Align, Deghost with integer Strength 0–100 (50 initially), Auto Crop, reference/result comparison, a magenta motion overlay with affected percentage, and full-resolution native detail from the first ready revision. A new revision cancels old processing. Prepared source strips are reused when the common reference stays unchanged and are checksum-validated when read. Merge only accepts a successfully prepared current revision. Successful publication selects the merged photo, opens it in the main preview, and reveals its gallery entry at the nearest viewport edge, including unloaded records. Completed publication tasks remain until dismissed and offer **Open result** to return to the photo later. Selection is unchanged when starting a task or when publication fails or is cancelled.

Noise mode requires effective exposures within 0.1 EV, including measured scales. HDR includes shutter and ISO variations and the verified BRK aperture exception. Effective exposure remains shutter × ISO ÷ aperture². White balance is common to the reference; the result has neutral independent edits and a reference-based white-balance reset. Lens corrections are fixed during preparation and subsequent UI/MCP lens patches are rejected.

## Native review interaction

Touchpad pinch and Ctrl-scroll zoom around the pointer; left-button dragging also pans within the image edges. The compact toolbar provides zoom steps, 10%–3200% presets, Fit and 100%. Double-click switches between Fit and 100%. With the viewport focused, **+ / −** zoom, **0** fits, **1** selects 100%, and arrow keys pan by 40 CSS pixels (120 with Shift). Forms, source/settings scrolling and the console retain their own controls. At 100%, one decoded review pixel occupies one CSS pixel, regardless of source catalog dimensions or display pixel ratio.

Mouse panning locks and hides the cursor, using relative motion to continue beyond viewport, window and screen edges. Releasing the left button restores the cursor; Escape ends the drag without closing the review. Window blur, resize, loading, revision changes and closing the review also release the lock. The photo preview shares this behavior. Touch, pen and denied or unsupported mouse locks retain pointer capture. A delayed lock grant after a cancelled drag is immediately released.

The result, prepared reference and motion overlay share validated native crop dimensions and one viewport transform. Settings, mode, reference and comparison changes preserve manual zoom and the normalized image center; resize and crop changes constrain pan. Each new review starts at Fit. Loading displays a neutral state, cancels dragging and rejects stale responses. Review presentation uses one viewport-sized WebGL2 canvas. The result, reference and overlay upload once per revision; wheel and pointer events accumulate their full geometry changes and draw at most once per animation frame. Overlay composition shares the image coordinates, with premultiplied filtering at transparent edges. Context loss replaces the surface and validates it before enabling Merge again. Closing, loading and revision changes release textures and decoded images and cancel pending frames.

While a merge dialog covers the workspace, the main photo renderer releases its presentation resources and pauses preview requests, working preparation and analysis. ## Algorithms and bounds

`sony-merge-v4` runs in the separate bundled Node worker and ships a pinned OpenCV 4.13.0 SIMD WASM module. Runtime files, checksums, licenses and reproducible build instructions are in [vendor/opencv](../vendor/opencv/README.md). No system OpenCV or runtime download is required. Existing v1–v3 masters, edit histories and interrupted publication journals remain readable. Recipes record preparation, alignment, radiometry, accumulation and reference-fallback policies and the actual backend. LibRaw retains the existing verified recording-mode guard. Preparation applies common reference white balance, orientation and fixed sensor-white normalization. Verified BRK HDR uses each source’s validated distortion, lateral chromatic-aberration and vignetting tables. A decoder probe establishes a common centered valid crop before any alignment; catalog dimensions do not define this crop. CPU preparation, GPU preparation and sensor accumulation use the same source tables and crop. Other merges retain reference lens preparation. Recipes and preparation/registration cache identities record the source lens identities, common crop and policies. Source saturation is captured from sensor sites before demosaicing and expanded by two pixels. Canonical CPU lens geometry repairs mask boundaries, preserving exact CPU/GPU clipping agreement. Values above white and signed Rec.2020 conversion values survive accumulation. The independent LibRaw CPU path remains available on GPU failure.

Alignment uses spatially capped ORB features, reciprocal ratio-tested Hamming matching, RANSAC similarity and bounded homography candidates, and OpenCV's masked ECC optimizer. Explicit validity masks exclude sensor clipping and unreliable shadows from alignment reduction, feature centers, interpolation and refinement. Alignment-only exposure normalization leaves accumulation values unchanged. At least 30 RANSAC inliers must span six cells of a 4 × 4 grid. Similarity is preferred when native validation passes; projective geometry is evaluated otherwise. Neighboring exposures form an alignment graph and can supply an intermediate path; no source is silently discarded.

Verified BRK preparation also retains separate native camera-channel evidence under `unclipped-camera-channel-v1`. Inverting the linear camera-to-working matrix preserves the source lens corrections and common white balance. Each channel has its own sensor clipping mask, expanded for the demosaic stencil and sampled through that channel's distortion/CA geometry; reduced samples require complete valid footprints and sufficient signal. The selected channel must improve common valid coverage across the reference, neighbor and source by at least two percentage points. RGB feature paths run first, followed by feature paths on this one selected channel if RGB cannot prove geometry. These paths use the same native, motion and parallax checks. Camera-channel validity never changes the stricter combined RGB masks used for radiometry or fusion. Diagnostics record the chosen channel; checksummed native strips and reduced channel planes form separate preparation evidence.

When both feature paths fail, the direct reference path tries at most two further masked pyramid ECC estimates on the original RGB luminance: similarity, then projective. Local contrast is computed separately at each pyramid level to suppress changing low-frequency illumination; a safe feature fit may initialize the optimizer. Each estimate must produce at least 30 coherent spatial patch correspondences with correlation ≥0.98 across six grid cells before geometry fitting. ECC correlation and identity alone never authorize a merge. Fitted candidates still require the independent native validation, motion/parallax checks, geometry bounds, coverage, exposure validation and reference-fallback limits below. Motion measurements are cached by starting matrix and tile field, with a bounded set per pair. Diagnostics retain early feature failures, rejected attempts, registration method, usable coverage and patch support counts, including when another attempt succeeds. Compatibility failures name the affected file.

All sampling uses inverse 3 × 3 matrices in native pixel-center coordinates. Preview conversion uses `(pixel + 0.5) × scale − 0.5`; area reduction uses fractional pixel footprints. Geometry rejects folds, singular matrices, local scales outside 0.9–1.1, rotations outside ±5°, center translations beyond 10%, and less than 70% shared coverage. Global candidates use sparse native training to refine the coarse fit, followed by an independent 11 × 11 grid with full native optimization. The full refinement helper retains its 12 × 12 training grid; rejected fast global candidates enter masked tile training rather than repeating global refinement. At least eight observable patches spanning six cells, and 70% of evaluated patches, must agree within 0.5 native pixels. A preliminary sparse training check can reject competing motions before expensive global refinement; it never replaces final validation.

Motion separation follows the masked, exposure-normalized coarse-to-fine tile approach described in [HDR+](https://research.google/pubs/burst-photography-for-high-dynamic-range-and-low-light-imaging-on-mobile-cameras/). Training patches covering 320 native pixels use immutable linear pyramids to propose coherent camera and subject motions; small pyramids retain the native sampling path. Two substantial incompatible planes are rejected as ambiguous parallax, including a fresh full-scene measurement after geometry refinement and before exclusions. Separate 160-pixel native training patches fit bounded camera residuals on a 16 × 16 field with independent 19 × 19 validation. ECC candidates use native 32 × 32 initial correspondences, denser 48 × 48 refinement, a 32 × 32 residual field and independent 35 × 35 validation. The field, exclusions and transforms freeze before validation: at least eight observable patches spanning four cells, and 70% of evaluated patches, must agree within 0.5 native pixels. Residual offsets stay within three pixels and retain the geometry checks. Unsupported regions exclude their source during deghosting. Synthetic passes alone do not establish real-scene quality.

Recipes record algorithm versions, alignment constants, native matrices and tile offsets, inlier distribution, independent patch offsets, source exclusions, alignment runtime and WASM heap size. Native review accumulation and recipe replay use the frozen transforms and exposure scales. Two alignment workers overlap completed-source registration with subsequent GPU preparation. Each WASM heap is capped at 256 MiB, preserving a combined 512 MiB allocation limit; every call releases its allocations. Immutable pyramids and descriptors stay within the review. Each alignment worker has a checksummed native luminance cache bounded to 192 MiB. Each source has at most three reference/neighbor attempts; exhaustion is an explicit failure. Native refinement yields between batches for foreground preview priority.

Exposure estimates start from shutter × ISO / aperture². Noise stacks and unverified HDR selections retain the 0.25 EV metadata and 0.1 EV median residual limits. Verified BRK HDR uses `brk-tiled-radiometry-v4`: sensor masks identify clipping, including when valid linear working values exceed one. Spatial tiles have disjoint training and validation samples. Harmonic signal weights favor well-exposed samples; capped tile weights preserve spatial balance. A coherent training mode freezes the exposure fit and source exclusions before held-out validation. At least 128 samples per half, eight retained tiles across four cells, ≥70% held-out agreement and ≤0.1 EV median residual are required. A competing substantial exposure mode or unsupported overlap fails. The managed-original trigger proof permits a bounded metadata discrepancy up to 1 EV. Recipes retain both nominal and measured exposure and all support/residual diagnostics; cache identities include the policy. Illumination outliers exclude only that source through the existing deghosting path and remain subject to the 95% reference-fallback limit.

For verified BRK HDR, source confidence tapers over 64 native pixels outside rejected regions before inverse-variance accumulation. Rejected pixels contribute no weight; the taper reduces weight only within otherwise verified support. Bands include a halo so batch boundaries cannot alter the confidence field. Before dilation or tapering, the final reference mask also freezes every covered pixel whose accumulation has no valid samples. This includes clipping gaps even when a surviving camera channel proved alignment. Adding these pixels during output would bypass the transition and create hard seams. The final reference fallback uses the same transition outside the complete frozen, dilated mask; rejected pixels use the complete fallback reference. Every pixel touched by fallback, including the transition, counts toward the 95% limit. CPU, prepared-band GPU and sensor GPU paths share the byte-quantized policy. The saved mask and review overlay retain transition strength. Other merges keep binary exclusions. Registration cache identities include the frozen exposure policy and taper radius; recipes also record the accumulation and fallback versions.

When a verified BRK reference contains saturated sensor sites, a separate CPU preparation supplies the highlight-safe reference for `sony-camera-highlight-blend-frozen-missing-reference-v4`. It applies the existing Sony HDR camera-stage highlight blend before common white balance, source lens corrections and working-color conversion. Only reference pixels marked invalid by the original canonical clipping mask take these prepared RGB values; valid reference pixels keep their original values. This reference supplies fallback and the review comparison, while alignment, radiometry, fusion and clipping decisions retain the original preparation. The blend preserves camera intensity and reduces clipped chroma; it does not restore missing detail. The fallback shares the common crop, is checksum-validated, and has a cache identity containing the reference preparation and highlight policy. Its CPU decoding/preparation costs and reuse appear separately in measurements. Acceptance still publishes the exact reviewed native master.

The exposure policy follows the spatial balance, signal weighting and metadata-prior principles in [Hanji and Mantiuk, Robust estimation of exposure ratios in multi-exposure image stacks (2023)](https://arxiv.org/abs/2308.02968). Their work explains why nominal EXIF ratios alone can produce HDR artifacts; it does not establish the physical cause of each Sony discrepancy. [Sony's continuous-bracket guide](https://helpguide.sony.net/dc/1910/v1/en/contents/TP0002846539.html) describes one held shutter trigger and exposure changes that depend on shooting mode and ISO settings. This implementation verifies the managed-original counters and actual linear overlap independently. It does not claim a calibrated Sony noise model or reproduce Lightroom processing.

The supplied brackets exhibit 0.30–0.52 EV discrepancies and spatial illumination changes. Noise estimates use versioned read and shot noise constants. Deterministic tiled GPU accumulation excludes sensor-saturated samples and weights normalized samples by inverse estimated variance. Independent CPU bands implement the same frozen recipe and remain the correctness reference and fallback.

Deghost strength changes a noise-normalized detection threshold; it does not crossfade two images. Registration uncertainty excludes only its source; another validated source remains usable. Pixels without a usable nonreference source and detected changing pixels form the expanded reference mask. A result requiring the reference over more than 95% of covered pixels fails. The overlay reports affected area and clipped-reference area. Mask dilation is conservative and manual region overrides remain unavailable. GPU motion is committed only after the entire attempt succeeds; a partial device failure cannot contaminate the independent CPU fallback. The supplied portrait pair/triple publication and native-detail gates passed in the v3 record below.
